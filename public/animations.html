Animations

Every animation here runs from the same formula and the same numbers as the C code, and each one names the file those numbers come from.

A zrnui app does not call any of these. libzrnui has no animation API at commit ea16771: page changes, presses, switches and toasts animate by themselves, and the style decides how. Swivel, fade and the other named transitions are not in libzrnui. They exist in ZrnMetroCore (ztOS's own apps) and in the older Python SDK's animate().

Using these demos

Replay runs it again. The speed button cycles 1x, 0.25x and 0.1x. The slider shows any single millisecond. Demos start when you scroll to them. If your system asks for reduced motion, nothing starts by itself and each demo rests on its last frame, so you can step through with the slider.

Where the web version only approximates
  • Same: durations, staggers, angles, pivots, opacity, easing formulas and the eye distance (a 34 degree field of view on a 740 pt tall screen, gfx.c, zrnmetrogpu.c). A browser's perspective is the same divide the shader does.
  • Different: the fonts and row layouts are plain CSS stand-ins, not Segoe UI through the SDF renderer. The real look is in the renders.
  • Different: the demos draw in the Metro look only. DotMatrix runs the same motion through its lattice, as the real frames show.
  • Different: phones here run at your browser's frame rate, not the S9's, and the C code samples its clock once per compositor frame.
  • Different: libzrnui rotates each row's quads, while these demos rotate a whole row box. Each named-transition demo shows one rectangle in a 300 pt tall stage, while the eye distance stays that of a 740 pt screen.
  • Not compared to the phone: these were compared by eye with frames from the laptop's virtual compositor, not with the S9's display.

The curves

Progress over time for each easing. libzrnui has three, in libzrnui/src/core.c: zui_ease_out is 1 - (1-t)^3, zui_ease_in is t^3, and zui_ease_emph is a cubic Bezier (0.2, 0.8, 0.2, 1). ZrnMetroCore rebuilds the firmware's named curves in zt_shape, with k = weight / 30: Exp is (e^(k t) - 1) / (e^k - 1) and Log is 1 - (e^(k (1-t)) - 1) / (e^k - 1). The firmware stores names and weights. The formula itself is a reconstruction, as the core's own comment says.

Page change: the turnstile libzrnui

Automatic on zui_push and zui_back, in both styles, with the same numbers. Runs 720 ms in all. Rows leave one at a time, 28 ms apart, each over 128 ms, turning 50 degrees about the left edge on zui_ease_in toward the viewer, with opacity 1 - u^2. New rows start at 330 ms, also 28 ms apart, each over 180 ms from 80 degrees behind the screen, on zui_ease_out. Going back, both run bottom up and the old rows turn the other way.

Source: page_xf, OUT_MS, IN_MS, STAGGER, GAP_AT in libzrnui/src/style-metro.c. The comment above them says 33 ms apart; the code that runs says 28.

Swivel: the domino board ztOS apps only

The jump grid and the pickers. Each of the 28 tiles turns about a horizontal line through its own middle, in reading order, and each starts while the one before is still moving.

AngleTimeCurveVisibility
In-45 to 0 degrees0.3 sLog 200opacity 0 at 0 s, 1 at 0.01 s
Out0 to 60 degrees0.2 sExp 150opacity 1 until 0.199 s, 0 at 0.2 s

These come from the Lumia 530 firmware's ANIMATIONS.UIX (SwivelTransitionIn at 0x3f29, SwivelTransitionOut at 0x3eb3), recorded in ztmetro/core/zrnboard.h as ZB_SWIVEL_*. The firmware fixes each tile's motion but not the stagger. The 12 ms step (ZB_STAGGER_MS) is ztOS's own choice, and so is using the same order going out. The source says which is which. Tile sizes are also from there and CONSTANTS.UIX: 99 wide with a 12 gap at 480, scaled by 0.75.

A picker adds fixed steps this demo leaves out: the box lit for 116 ms, the page gone in 50 ms, the surface in 33 ms (ZB_BOX_MS, ZB_PAGE_OUT_MS, ZB_PAGE_IN_MS).

Press and tilt libzrnui

Press a row in this demo: it follows your pointer. What is under the finger leans toward it by up to 14 degrees, but its far edge never lifts more than 40 pt, and it sinks 4.5 %. Rows tilt. Sliders and fields do not move, and a button fills instead. In takes 90 ms, and the release takes 200 ms (160 ms when the press is cancelled by a scroll), all on zui_ease_out. DotMatrix uses the same press_xf.

Source: press_xf, TILT_DEG, TILT_LIFT, PRESS_SINK in style-metro.c, timing in core.c. ZrnMetroCore shares the numbers (ZMC_TILT_*).

Older Python SDK: where its numbers differ older

ztos.animate(widget, name, repeat=False, on_done=None) plays a named transition over any Qt widget. Its table is TRANSITIONS in sdk/runtime/ztos/__init__.py. Most entries match the list above, but its swivel predates the firmware decode now in zrnboard.h:

ZrnMetroCore (firmware)Older Python SDK
swivel-in-45 to 0, 300 ms, Log 200, no fade-60 to 0, 300 ms, Log 200, fades 0 to 1
swivel-out0 to 60, 200 ms, Exp 150, no fade0 to 60, 199 ms, Exp 60, fades 1 to 0
Press in, out90, 200 ms70, 160 ms, divided by the menu speed setting
Row out128 ms110 ms, divided by the menu speed setting

Everything else that moves in that SDK is also scaled by ANIM_SPEED, which comes from a user setting, so its real durations vary.
