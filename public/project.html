Project layout

An app is a CMake project with a CMakePresets.json. The store reads zrnapp.toml (app id, version, permissions, [build] sdk = 2); see Publish to the store.

CMakeLists.txt

This is the whole of examples/helloworld/CMakeLists.txt:

cmake_minimum_required(VERSION 3.16)
project(helloworld C)

set(CMAKE_C_STANDARD 23)
set(CMAKE_C_STANDARD_REQUIRED ON)
set(CMAKE_C_EXTENSIONS OFF)

add_subdirectory(../../zrnapp ${CMAKE_BINARY_DIR}/zrnapp)

add_executable(helloworld hello.c)
target_link_libraries(helloworld PRIVATE zrnapp::zrnapp zrnui::zrnui)

Outside the checkout, point add_subdirectory at your copy of zrn-sdk/zrnapp. With an installed SDK use pkg-config instead:

cc -std=c23 app.c $(pkg-config --cflags --libs zrnapp zrnui) -o app

Or in CMake: pkg_check_modules(ZRN REQUIRED IMPORTED_TARGET zrnapp zrnui) and link PkgConfig::ZRN. There is no CMake package file.

Presets

PresetForBuild directory
host-debug, host-releaseThis computerbuild/host-<type>
phone-debug, phone-releaseA phone (aarch64 Arch Linux ARM), cross build with clang and a sysroot. zrnui and zrnapp are linked statically, no testsbuild/phone-<type>

Copy CMakePresets.json from an example. Its phone presets point at ../../cmake/toolchain-aarch64.cmake, so fix that path if your app lives elsewhere. Your own presets go in CMakeUserPresets.json. CLion, VS Code, Qt Creator and Visual Studio read the presets.

The app id

The shell matches a window to its .desktop file by app id. zrnapp takes it from ZWindowOptions.app_id, else $ZRNAPP_APP_ID, else the file name of the executable. The title in ZWindowOptions.title is for people.

const ZWindowOptions window = { .title = "Notes", .app_id = "zrn-notes" };
Zwindow_run_ex(root, &window);

Installing the SDK

cmake --install zrnui/build --prefix /usr/local
cmake --install zrnapp/build --prefix /usr/local     # configured with -DZRNAPP_SYSTEM_ZRNUI=ON

On Arch Linux each part has a PKGBUILD. Build zrnui first, then zrnapp.
